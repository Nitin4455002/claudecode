Service Schema

Service schema tells Google what service you offer, who provides it, where it is available, and how much it costs. Use this schema for agencies, studios, consultants, and any service-based business with a Framer website. This guide covers every field in the RankFrame Service schema form.

What service schema does

Service schema describes a service offering to Google. It provides structured information about what the service is, who offers it, the geographic area it covers, contact details, and pricing. Google uses this data to understand service-based businesses and match them with relevant queries in local and general search results.

This schema type is ideal for Framer sites representing agencies, design studios, consulting practices, SaaS companies, legal firms, financial advisors, and any business whose primary offering is a service rather than a physical product.

Service Schema Setup & Available Options

Now let's have a closer look at each of the available options in detail. The form contains nine fields across two groups: service details and contact and pricing.

Service Details

1
Service Name

Enter the name of the specific service you are marking up (for example, "Brand Identity Design", "SEO Consulting", or "Web Development"). If you offer multiple services, create a separate schema entry for each one bound to its own page. Use the exact name you use in your proposals, invoices, and service pages. This value populates the name property in the JSON-LD output.

2
Description

Write a 1 to 3 sentence description of what the service includes, who it is for, and what outcome it delivers (for example, "We design brand identities for early-stage startups. Each project includes logo, color system, typography, and brand guidelines."). Write in a way that would attract your audience as well as help Google understand the service. This value populates the description property.

3
URL

Enter the canonical URL of the page describing this service (for example, https://yourdomain.com/services/seo). This should be the permanent, preferred address for this service page. Each service schema should point to its own dedicated page URL. This value populates the url property in the JSON-LD output.

4
Service Type

Enter a clear descriptive label for the category of service you provide (for example, "Web Design", "Digital Marketing", "Legal Consulting", "Financial Planning", or "Software Development"). This helps Google classify the service and match it to relevant search queries. Use the same label consistently across your schema entries and service pages. This value populates the serviceType property.

5
Provider Name

Enter the name of the person or organization providing this service (for example, "7 Seers" or "Jane Smith Consulting"). This links the service to an identifiable entity. Use the same name that appears in your Organization or Person schema entries to reinforce the entity signal across your schema. This value populates the provider.name property.

6
Area Served

Enter the geographic region where this service is available (for example, "New York", "United States", "Europe", or "Worldwide"). For fully remote or digital services, use "Worldwide" or "Remote". For local or regional services, be as specific as possible: "Brooklyn, New York" is more useful than just "United States". This value populates the areaServed property.

Contact and Pricing

7
Telephone

Enter the contact phone number for inquiries about this service, including the country code (for example, +1-555-234-5678 or +91-98765-43210). Leave this field empty if you do not accept phone inquiries for this service. This value populates the provider.telephone property in the JSON-LD output.

8
Price

Enter the price for the service as a number (for example, 1500 for a flat rate, or the starting price for variable pricing). Do not include currency symbols in this field. If pricing is entirely custom or quote-based, you can leave this field empty. The schema remains valid without pricing data. This value populates the offers.price property.

9
Currency

Enter the ISO 4217 three-letter currency code for the price entered in the Price field (for example, USD for US dollars, EUR for euros, GBP for British pounds, INR for Indian rupees, AUD for Australian dollars). This must match the currency of the amount in the Price field. This value populates the offers.priceCurrency property.

Tip

For agencies or studios with multiple service offerings, create a separate Service schema entry for each service and bind each to its own page URL. For example, create one entry for Brand Design on /services/brand and another for Web Development on /services/web.

Saving and injecting

  1. Click the Preview JSON tab to review the complete JSON-LD output for this service.
  2. Click Validator (Ext) to open Google Rich Results Test and confirm the schema is valid.
  3. Click Copy JSON if you want a copy of the raw JSON-LD.
  4. Click Save Schema to save it to the Manual sub-tab in Saved Schemas.
  5. Toggle the schema on in Saved Schemas, then click Save and Inject.

Frequently asked questions

Who should use Service schema?
Any business or freelancer that offers a service. This includes agencies, design studios, consultants, software companies, marketing firms, law firms, and any other service-based business with a Framer website.
What should I enter for Service Type?
A clear descriptive label for the category of service. Examples: Web Design, SEO Consulting, Brand Strategy, Software Development, Legal Services, Financial Consulting.
What should I enter for Area Served?
The geographic region where you provide your service. This can be a city, state, country, or a general description like Worldwide or Remote. For fully remote services, use Worldwide.
What currency format should I use?
Use the ISO 4217 three-letter currency code: USD for US dollars, EUR for euros, GBP for British pounds, INR for Indian rupees. The Price field takes a number and Currency takes the code.
