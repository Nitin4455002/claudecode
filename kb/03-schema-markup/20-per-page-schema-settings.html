Per-Page Schema Settings

Global schema applies to every page by default. Per-page schema lets you assign a different schema type and custom fields to individual pages, overriding the global setting exactly where it matters.

Global vs per-page schema

RankFrame has two layers of schema control. The global layer sets the default schema type and fields for all pages. The per-page layer overrides the global settings for any specific page where a different schema type is more appropriate.

Setting Global schema Per-page schema
Applies toAll pages by defaultOnly the page it is set on
Schema typeOne type for the whole siteAny type, specific to this page
FieldsShared across all pagesFields specific to this page
Best forHomepages, consistent site typesBlog posts, service pages, product pages
OverrideBase settingTakes full priority over global

When to use a per-page override

Most Framer sites need at least a few per-page overrides. Here are the most common cases.

  • Blog posts in a CMS collection
    Override type: Article or BlogPosting
    If your global type is Organization, blog posts need Article schema to get author, date, and publisher fields in search results.
  • Service or feature pages
    Override type: Service
    Each dedicated service page describes one offering. Service schema lets you specify the service name, provider, type, and area served precisely.
  • FAQ page
    Override type: FAQPage (or add alongside primary type)
    FAQ schema unlocks expandable question dropdowns in Google search results. It is only valid on pages that actually contain a list of questions and answers.
  • About or team page
    Override type: Person (for personal brands) or Organization
    An about page focused on an individual founder benefits from Person schema rather than the company-level Organization type.
  • Product landing page
    Override type: Product
    Product schema lets you surface price and availability in search results, which Organization schema cannot do.

How to set per-page schema

  1. 1
    Go to Per-Page SEO in RankFrame
    Open RankFrame in Framer and select Per-Page SEO from the left navigation.
  2. 2
    Select a page from the list
    Click the page you want to configure. The per-page settings panel opens on the right.
  3. 3
    Open the Schema section
    Scroll to the Schema section within the per-page panel. You will see the current schema source: either inherited from global or a custom override.
  4. 4
    Enable Override global schema
    Toggle on Override global schema for this page. The schema type dropdown and field editor become active.
  5. 5
    Select a schema type and populate fields
    Choose the schema type from the dropdown. Fill in the fields manually or click Generate with AI to have RankFrame draft them. AI generation uses 1 credit for this page.
  6. 6
    Save the per-page schema
    Click Save. RankFrame marks this page as having a custom override. The global schema is no longer applied to this page. The override schema is injected on the next Framer publish.
Tip

Pages with an active override show an Override badge in the page list. Use this to quickly audit which pages have custom schema and which are inheriting from global settings.

Disabling schema on a page

Some pages should not have schema injected at all. Utility pages like thank-you pages, login screens, or redirect landing pages do not benefit from structured data and can dilute schema quality signals if marked up incorrectly.

To disable schema on a specific page:

  1. Open the per-page settings for the page.
  2. Enable Override global schema for this page.
  3. Select No schema from the type dropdown.
  4. Click Save.

RankFrame will skip schema injection for this page on all future publishes.

Per-page schema for CMS items

CMS collection items from your Framer site appear in the Per-Page SEO list alongside static pages. Each collection item can have its own schema override, the same as any static page.

For blog collection items, the recommended approach is:

  • Set Article or BlogPosting as the override type for each item
  • Map the CMS title field to schema headline
  • Map the CMS author field to schema author.name
  • Map the CMS published date field to schema datePublished
Note

CMS field mapping is done in the per-page schema editor for collection items. The field mapping UI shows your available CMS fields on the left and the corresponding schema properties on the right. Mapped fields update automatically when CMS content changes and you republish.

Frequently asked questions

What happens to a page that has no per-page schema override?
Pages without a per-page override inherit the global schema type and fields set in Global SEO Settings. The global schema is injected for those pages on every publish.
Can I disable schema for a specific page?
Yes. In the per-page schema settings, you can select No schema for this page to exclude a specific page from schema injection entirely. Useful for utility pages like thank-you pages, confirmation screens, or login pages.
Does per-page schema override the BreadcrumbList schema too?
No. BreadcrumbList schema is always generated from the page's breadcrumb navigation and its canonical URL. It is not affected by per-page schema type overrides.
How do I apply per-page schema to CMS collection items?
CMS collection items appear in the Per-Page SEO list alongside static pages. Select any collection item to configure its schema individually. For blog collections, Article or BlogPosting schema is recommended for every item.
