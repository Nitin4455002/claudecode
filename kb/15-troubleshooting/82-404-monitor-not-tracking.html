Troubleshooting

Fixing 404 Monitor Not Tracking

The 404 Monitor uses a lightweight script injected on your Framer site to catch and log every 404 error as it happens. If the monitor is showing no errors when you expect some, or is logging false positives, the issue is almost always in the script toggle, the allowed domains list, or the exception routes configuration.

404 Monitor Setup Checklist
  • Script toggle is turned on in Global Settings > 404 Monitor tab
  • Your live domain is entered correctly in Allowed Domains (no https://, no trailing slash)
  • Your Framer site has been published since you enabled the toggle
  • Intentional catch-all paths are added to Exception Routes so they are not logged as errors
1 Script Toggle Is Off
CauseThe 404 Monitor Script toggle in the Global Settings 404 Monitor tab is disabled. When off, no monitoring happens at all.
FixFixOpen Global Settings > 404 Monitor tab and flip the toggle on. Then publish your Framer site to push the script change live.
Global Settings > 404 Monitor tab showing the script enable toggle in the off position
2 Wrong Domain in Allowed Domains
CauseThe domain in Allowed Domains does not match your live site domain exactly, so the script ignores all incoming 404 events.
FixFixCheck the Allowed Domains list, remove any incorrect entries, and add your exact live domain. Enter it without https:// and without a trailing slash (for example: yourdomain.com).
404 Monitor tab showing the Allowed Domains input field with a correctly formatted domain entry
3 New Site Not Yet Published
CauseThe monitoring script is injected at publish time. Enabling the toggle in RankFrame schedules the script for the next publish, but it is not active until you publish.
FixFixPublish your site in Framer, then wait for real visitors or bots to trigger 404 errors. The errors will appear in the table as they happen.
Framer publish button confirming the site was published after enabling the 404 monitor script
4 No Real 404 Errors Yet
CauseThe monitor is working correctly but your site genuinely has no broken URLs. This is the best possible outcome.
FixFixNo action needed. Errors will appear automatically when real users or bots hit broken URLs on your site.
404 Monitor error table showing an empty state with no errors logged
5 Too Many False Positives
CausePaths you use intentionally, such as catch-all routes or redirect testing paths like /404, are appearing as errors in the monitor table.
FixFixAdd those paths to Exception Routes in the 404 Monitor tab. Use the input field (placeholder reads /path-to-ignore) and click + Add. Paths listed in Exception Routes are ignored by the monitor going forward.
404 Monitor tab showing the Exception Routes input field with a path added and the + Add button
6 Total Errors Showing but Table Is Empty
CauseThe domain filter dropdown is set to a specific domain that has no errors logged, while other domains do have errors.
FixFixSet the domain dropdown above the errors table to All Domains to see every logged error across all your domains.
404 Monitor errors table with the domain filter dropdown set to All Domains

Frequently Asked Questions

How quickly do 404 errors appear in the monitor after the script is enabled?
Errors appear in the 404 Monitor table in real time as they are triggered by visitors or bots. The script only runs after you publish your Framer site with the toggle enabled. If you enabled the toggle but have not published yet, the script is not active and no errors will be logged.
Does the 404 monitor script slow down my Framer site?
No. The 404 monitor script is lightweight and only fires on pages that return a 404 response. It has no impact on the load performance of your normal pages.
How do I clear old false-positive errors from the 404 monitor table?
Add the path to Exception Routes in the 404 Monitor tab so it will not be logged going forward. To remove existing logged entries from the table, contact hello@7seersmedia.com and the support team can clear specific entries from your error log.
What does the Unique Routes stat in the 404 Monitor mean?
Unique Routes shows the number of distinct URL paths that have triggered a 404 error, regardless of how many times each path was hit. For example, if /old-page was hit 50 times, it counts as 1 unique route. This helps you prioritize which broken URLs to fix first.
How do Exception Routes interact with Framer's native /404 page?
Framer serves your custom /404 page whenever a visitor hits a URL that does not exist. The RankFrame 404 monitor script detects this and logs the original URL that triggered the 404. If you add /404 to Exception Routes, the monitor will ignore hits directly to the /404 path, but will still log other broken URLs that result in the 404 page being shown.
