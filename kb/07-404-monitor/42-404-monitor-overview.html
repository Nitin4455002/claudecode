404 Monitor Overview

RankFrame's 404 Monitor automatically catches every broken link on your Framer site, so you can find and fix them before they hurt your rankings or frustrate visitors.

What the 404 Monitor does

Every time a visitor or search engine crawler lands on a URL that does not exist, your server returns a 404 status code. Those errors are silent by default. RankFrame's 404 Monitor adds a lightweight script to your live site that intercepts those responses and logs the broken route, the user agent that triggered it, and exactly how many times it has happened.

The result is a continuously updated error table inside RankFrame that tells you which pages are broken, which bots or browsers are hitting them, and how urgent each one is to fix.

Why this matters for SEO

Broken links waste crawl budget and signal poor site quality to search engines. Catching them early keeps your site healthy and your rankings stable.

Where to find it

The 404 Monitor is not a standalone sidebar section. It lives inside Global Settings under the 404 Monitor tab. Open RankFrame, navigate to Global Settings, and click the 404 Monitor tab to see all controls and the errors table.

Global Settings > 404 Monitor tab

How to set it up

Follow these steps to activate monitoring on your live site.

  1. 1
    Open Global Settings
    In the RankFrame panel, click Global Settings at the top of the navigation.
  2. 2
    Go to the 404 Monitor tab
    Click the 404 Monitor tab. You will see the subtitle "Keeps track of all 404 errors on the website."
  3. 3
    Enable the monitoring script
    Toggle the 404 Monitor Script switch to on. This injects the tracking script into your published Framer site. The toggle has no effect until you publish.
  4. 4
    Add your allowed domains
    In the Allowed Domains field, type your domain (for example, yourdomain.com) and press Enter to add it as a tag. Add every domain you want the script to monitor. You can remove a domain by clicking the X on its tag.
  5. 5
    Publish your Framer site
    Publish from Framer as normal. Once the site is live with the script active, 404 errors will begin appearing in the errors table automatically.
Important

The monitoring script only runs on your published live site. Errors will not be recorded in Framer's preview or staging environments.

At-a-glance stats

At the top of the 404 Monitor tab, two summary numbers give you a quick read on site health.

  • Total 404 Errors shows the cumulative count of all 404 responses recorded across all monitored domains.
  • Unique Routes shows how many distinct URL paths have returned a 404. One route can be hit many times; this number tells you how many separate broken URLs exist.

For example, a site might show 12 total errors but only 7 unique routes, meaning several paths have been hit multiple times.

Status indicator

At the bottom of the tab, a status indicator confirms whether the monitoring script is active.

Monitoring script active, 404 errors are being tracked

A green dot alongside that message means RankFrame is connected and collecting data. If the script toggle is off, the indicator will reflect an inactive state instead.

Trial users

Trial users have full access to the 404 Monitor with no data limits. Every error is tracked from day one of your trial. There is no artificial cap on the number of errors or routes that can be recorded during the trial period.

Frequently asked questions

Do I need to add code to Framer manually?
No. RankFrame injects the monitoring script automatically when the 404 Monitor Script toggle is on. There is nothing to paste into Framer's custom code fields.
Can I monitor more than one domain?
Yes. Add each domain as a separate tag in the Allowed Domains input. You can also filter the errors table by domain once you have multiple domains set up.
What happens if I turn the toggle off?
The script will be removed from your site on the next publish. New errors will stop being recorded, but existing data in the errors table is preserved.
My custom 404 page is showing up in the error log. Is that normal?
Yes. Your /404 route intentionally returns a 404 status, so the monitor picks it up. Add /404 to the Exception Routes list to exclude it from the log. See the Exception Routes article for details.
