What is a 404 Error? How to Find and Fix Them (2026)

By RankFrame Team  ·  May 4, 2026  ·  13 min read

A 404 error is the HTTP status code a web server returns when a browser or crawler requests a URL that does not exist on the server. The full name is "404 Not Found." The server has received the request, understood it, and confirmed that there is no resource at that address. 404s happen for many reasons (deleted pages, moved pages without redirects, typos in URLs, broken internal links, broken external backlinks) and while individual 404s are normal, accumulating 404s on a site signals neglect, wastes crawl budget, and quietly destroys link equity. This guide explains what 404s are, when they help and hurt, how to find them, and how to fix them properly.

What is a 404 Error?

A 404 is one of the HTTP status codes defined in the original HTTP specification. Status codes are three digit numbers a web server includes in every response telling the client what happened with the request. The 4xx family signals a client error (the request was bad in some way). The 404 specifically means "Not Found." The server is reachable, the request was syntactically valid, but no resource exists at the requested URL.

When a browser receives a 404, it typically shows the server's custom 404 page if one is configured, or a generic browser error page. When a crawler receives a 404, it removes the URL from its crawl queue and over time drops it from the search index.

The 404 status is technically distinct from the 410 (Gone) status, which means the resource existed at this URL previously and has been deliberately removed. In practice, search engines treat 404 and 410 almost identically, with 410 sometimes triggering slightly faster removal from the index. Most servers and CMS platforms only return 404 because it covers both meanings without requiring the publisher to distinguish.

How 404 Errors Happen

404s appear for many reasons. Knowing the cause is the first step to deciding the right fix.

1. A page was deleted

The most common cause. A blog post is removed, a product is discontinued, a campaign landing page is unpublished. The URL is no longer served by the CMS, and any request to that URL now returns 404. If anything still links to the deleted page (internal navigation, an old social post, a backlink from another site), the 404 is exposed every time someone clicks.

2. A page was moved without a redirect

Renaming a URL slug, restructuring categories, or migrating to a new CMS often changes URL paths. If the original URL is not redirected to the new one with a 301, the old URL returns 404. This is one of the most damaging causes because the page still exists, just at a different address, and ranking signals from the old URL evaporate.

3. Typos in URLs

Visitors typing a URL by hand may misspell it. Authors writing internal links may mistype a slug. Email campaigns and social posts may include a URL with an extra character. All of these produce 404s when followed.

4. Broken internal links

An internal link pointing to a slug that no longer exists, or to a CMS item that has been unpublished, generates a 404 every time it is clicked. These are the most fixable 404s because both ends of the link are under your control.

5. Broken external backlinks

Other websites linking to your old URLs continue to send traffic to those URLs even after you remove the page. Each click results in a 404 for the visitor and a missed opportunity to capture inbound traffic and link equity.

6. Server or CMS misconfiguration

Misconfigured rewrite rules, broken plugins, or accidentally renamed template files can produce 404s for entire sections of a site. These are usually rapidly discovered because they affect many URLs at once and traffic drops sharply.

Hard 404 vs Soft 404

The terms hard 404 and soft 404 describe two different situations that look similar to a user but behave very differently for crawlers.

Hard 404

A hard 404 is the correct, standards compliant version. The server returns an HTTP 404 status code in the response headers, and the response body usually contains a "Page Not Found" message. Crawlers see the 404 status and treat the URL as deliberately missing. The URL is dropped from the index over time. Hard 404s are healthy when used for genuinely missing pages.

Soft 404

A soft 404 is when a page looks missing or empty to a user but the server returns an HTTP 200 OK status code instead of 404. Common examples include:

  • A search result page with no results that says "No results found" but returns 200.
  • A category page with no items that displays an empty grid but returns 200.
  • A custom 404 page implementation that forgets to set the 404 status code (a common bug on JavaScript single page apps).
  • A CMS template page that loads with placeholder or fallback content because the underlying record is missing.
  • A redirect to the homepage when the requested URL does not exist (homepage returns 200, search engines see a normal page that does not match the requested URL).

Google detects soft 404s through content analysis. When it finds them, it labels the URL as "Soft 404" in the Pages report under Indexing in Search Console. Soft 404s are problematic because they confuse the crawler about whether the URL is real, waste crawl budget, and signal poor site quality. The fix is to either return a real 404 status or, if the page should exist, restore the missing content.

Do 404 Errors Hurt SEO?

The short answer is yes, but indirectly more than directly. Google has stated repeatedly that 404s themselves are normal and expected. Returning a 404 for a deleted page is correct behaviour and does not directly harm a site's overall ranking.

The indirect impacts, however, are real and significant:

Wasted crawl budget

Googlebot has a finite crawl budget per site. Every 404 it has to revisit (especially repeatedly) consumes crawl budget that could have been spent crawling real pages. On large sites with many 404s, this becomes a measurable drag on how quickly new and updated pages get crawled.

Lost link equity

If an external site links to a page on your site that now returns 404, the ranking value of that backlink is lost. The link is technically still there, but it points to nothing. A 301 redirect to a relevant live page recaptures most of that equity. A 404 does not.

Broken internal link graph

Internal links pointing to 404s break the flow of PageRank through your site. Important pages may get less internal authority than they should because the path of links connecting them is broken at one or more nodes.

User experience and engagement

A visitor who clicks a link and lands on a 404 typically leaves the site within seconds. Bounce rate, time on site, and pages per session all suffer. Google increasingly weighs user engagement signals, especially in competitive niches, so a site littered with 404s sends weak engagement signals on top of weak technical signals.

Brand trust

Frequent 404s make a site feel neglected, broken, or unprofessional. This is harder to measure but affects conversion rate, brand perception, and willingness to share content.

When 404s Are Perfectly Fine

Not every 404 needs to be fixed. There are many situations where a 404 is the correct response:

  • Genuinely deleted pages with no relevant replacement. If you remove a blog post that is no longer accurate and there is no equivalent updated version, returning 404 is honest.
  • Discontinued products that have no successor. If a product line is permanently discontinued, a 404 is appropriate (some sites prefer to redirect to a parent category instead, both are acceptable).
  • Spam or malicious URLs that crawlers attempted from a guess based on URL patterns. These should 404.
  • Old test or staging URLs that were briefly public during development. 404 is the right cleanup.
  • URLs from a previous CMS that genuinely no longer have a counterpart and have no inbound links worth recovering.

The key question to ask for each 404 is: does anything still link to this URL, and is there a relevant live page that the linker probably wanted? If yes, fix it with a 301. If no, leave it as a 404. Forcing redirects from every 404 to the homepage is a common mistake that creates soft 404s and confuses Google.

How to Find 404 Errors on Your Site

You cannot fix what you cannot see. Multiple tools surface 404s with different strengths. A complete audit uses several together because each catches a different subset.

Google Search Console

The most authoritative source for 404s that affect SEO. Open Search Console, navigate to Indexing then Pages, and look for the "Not found (404)" bucket. This is the list of URLs Googlebot has actually tried to fetch and received a 404 for. It includes URLs Google found through its own discovery (sitemap, internal links, external backlinks, historical indexing memory). Click into the bucket to see the full URL list and the source of discovery for each.

Screenshot suggestion: Google Search Console Pages report with the "Not found (404)" row highlighted, showing example URLs in the table below.

Screaming Frog SEO Spider

Screaming Frog crawls your site like Googlebot would and reports every 404 it encounters. It also tells you which page contains the broken internal link, which makes fixing internal references straightforward. The free version crawls up to 500 URLs. Paid licences remove the limit.

Ahrefs Site Audit and Semrush Site Audit

Both tools crawl your site on a schedule and report 404s in dedicated issue categories. They also surface 404s on URLs that have backlinks from other sites, which is the most valuable subset to fix because each one represents lost link equity that you can recapture with a 301.

Server access logs

Server logs record every request that hit your server, including 404s, with the referrer header showing where the visitor came from. Log analysis catches 404s from real visitor traffic that crawl-based tools may miss (visitors typing URLs, following old emails, or coming from sites that crawlers have not discovered). On Framer hosted sites, server logs are not directly accessible, so this method applies mainly to self hosted setups.

Analytics tools

Google Analytics 4 does not track 404s natively but you can configure a custom event that fires when a custom 404 page is loaded. Some analytics setups send the referrer URL with the event, giving you the same picture as server logs without needing log access.

How to Fix 404 Errors

Once you have a list of 404 URLs, work through them by priority. URLs with backlinks from other sites are the highest priority. URLs with internal links from your own site are the second priority. Random URLs with no links and no traffic can usually be left as 404.

1. 301 redirect to a relevant page

The best fix in most cases. A 301 (Moved Permanently) redirect tells browsers and crawlers that the URL has permanently moved and provides the new location. Most ranking signals from the old URL pass to the destination. The 301 should point to the most relevant live page, not the homepage. Redirecting all 404s to the homepage creates soft 404s and damages user experience.

2. Restore the original URL

If a page was deleted by mistake or is still relevant, the simplest fix is to restore the content at the original URL. The 404 disappears the moment the page returns. Crawlers will recrawl the URL and update the index within days.

3. Fix broken internal links

For 404s caused by typos or outdated internal links, edit the source page and correct the link. This stops new visitors and crawlers from hitting the 404 in the first place. Use Screaming Frog's "inlinks" report to find the source pages quickly.

4. Reach out for backlink corrections

For high value backlinks pointing to a 404 (a link from a major publication, a Wikipedia citation, a guest post on an authority site), email the linking site and ask them to update the URL. Most editors are willing to fix broken links on their pages. This is more labour intensive than a redirect but produces a cleaner long term result.

5. Leave it as 404 (deliberately)

For URLs that should genuinely no longer exist, a clean hard 404 is the correct outcome. Make sure your custom 404 page is well designed, returns the correct status code, and helps the visitor find their way back into your site.

How to Design a Great Custom 404 Page

A custom 404 page is the brand-friendly version of the server's "Page Not Found" message. Done well, it turns a dead end into an opportunity to keep the visitor on your site. The essentials:

  • Match the rest of your site. Same header, footer, navigation, typography, and brand voice. The visitor should feel like they are still on your site, not crashed into a server error.
  • Explain clearly that the page they tried to reach was not found. Avoid technical jargon. A short, human message works better than "ERR_HTTP_404."
  • Include a search box so the visitor can search for what they were looking for.
  • Link to your top pages or main sections (homepage, products, blog, contact). Give the visitor several escape routes.
  • Add a touch of personality if it fits your brand. Many memorable 404 pages use illustration, humour, or a small interactive element. This is not required but it leaves a positive impression.
  • Critically, return an HTTP 404 status code. The page can look beautiful and friendly but if it returns 200, it is a soft 404 in Google's eyes.

404 vs 410 vs 301 vs Soft 404

Status What it means Effect on SEO When to use
404 Not Found Resource does not exist at this URL URL drops from index over time. No link equity passed. Page genuinely deleted, no replacement.
410 Gone Resource existed but has been permanently removed Same as 404 but Google may drop the URL slightly faster. Permanent removal where you want fast deindexing.
301 Moved Permanently Resource has permanently moved to a new URL Most ranking signals pass to the destination URL. Page moved, renamed, or replaced by an equivalent page.
Soft 404 Page looks missing but returns HTTP 200 Treated as quality issue. Excluded from index. Wastes crawl budget. Never. Always fix.

The choice between 404 and 410 is rarely consequential. Both eventually deindex the URL. The choice between 404 and 301 matters significantly because a 301 preserves the value of any external links pointing to the old URL while a 404 lets that value dissipate.
